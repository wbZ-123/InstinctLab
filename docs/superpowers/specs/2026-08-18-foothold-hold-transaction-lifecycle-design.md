# Foothold HOLD Transaction Lifecycle Design

## Goal

保证每个稳定 HOLD 规划事务最多评估一次学习式落足提案，避免同一个不安全提案在连续控制周期中被重复采样、重复计入 PPO 奖励，同时保留安全名义落足点回退。

## Root cause

当前 `learned_foothold_evaluated` 同时承担两个不同生命周期的职责：

1. 当前控制步是否产生 planner 奖励事件；
2. 当前 HOLD 事务是否已经完成 planner 评估。

该字段每个控制周期都会清零。学习式落点不安全但名义落点安全时，本应记录一次负奖励并结束本次规划事务；实际却会在下一个控制周期重新采样和再次扣分，直到 HOLD 结束。这样会让 `mean_reward_1` 随 HOLD 持续时间累积下降，而且真实执行的仍是名义落点。

## Design

将两个职责拆分为两个字段：

- `learned_foothold_evaluated`：单控制步奖励脉冲。每个控制周期开始时清零；仅在本周期确实评估新提案时置真，供 reward、PPO event mask 和监控读取。
- `learned_foothold_transaction_evaluated`：HOLD 事务锁存状态。提案完成评分后置真，普通控制周期不清零。

事务锁存状态只在以下边界清零：

- 环境 reset；
- 开始一笔新的 HOLD 规划事务；
- 支撑关系丢失或进入物理 Recovery，当前事务被废弃；
- 学习点与名义点都不可执行，代码明确废弃当前事务并开始一次新的重试。

正常数据流为：

```text
新 HOLD
→ 生成名义落点
→ 学习式 planner 评估一次并发出一次奖励脉冲
→ 锁存“本事务已评估”

学习点安全
→ 使用学习点进行轨迹预检查

学习点不安全、名义点安全
→ 学习点保留一次负奖励
→ 使用名义点
→ 不重新采样学习点

学习点和名义点都不可执行
→ 不进入危险 SWING
→ 明确废弃当前事务
→ 后续重试被视为一笔新事务
```

## Compatibility constraints

- 不修改 planner 正奖励公式或权重；修复轨迹预检查失败惩罚，使所有
  planner 单次奖励严格限制在 `[-1, 1]`。
- 不修改 planner PPO 学习率、KL、熵或探索方差。
- 不修改电机 PPO、AMP、MoE、课程和摆动轨迹跟踪逻辑。
- 不允许不安全学习点直接进入 SWING。
- 保持已有安全名义点回退行为。

## Tests and acceptance criteria

1. 学习点不安全、名义点安全：连续更新同一 HOLD 时只产生一次奖励事件，不改变第一次提案，最终使用名义点。
2. 学习点安全且轨迹预检查通过：只产生一次奖励事件并锁定学习点。
3. 学习点轨迹预检查失败、名义点通过：学习点只记一次失败，回退名义点，不重新采样。
4. 学习点和名义点都不可执行：不能进入 SWING；只有明确重开事务后才能再次评估。
5. 新 HOLD、reset、支撑丢失和 Recovery 会清除事务锁存状态，允许下一笔事务产生一次新事件。
6. 落足模块完整测试通过；静态检查确认单步事件脉冲不会被用于判断 HOLD 是否完成。
7. 后续短训中，planner 评估次数与规划事务次数应接近一一对应，不再出现同一 HOLD 十余次重复评估。
8. 轨迹预检查失败的单次 planner 奖励为 `-1`，不得出现 `-2` 或更低值。

## Non-goals

本修复不试图通过调参提高 planner 分数，也不调整楼梯感知、落点安全阈值或轨迹奖励权重。若修复后仍存在安全分下降，再基于一次事务一个样本的新数据分布单独诊断。
